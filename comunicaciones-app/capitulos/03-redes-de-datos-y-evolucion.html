Redes de Datos y Evolución

CAPÍTULO 3 — REDES DE DATOS Y EVOLUCIÓN

3.1 ¿Qué es networking?

El objetivo básico de una red es permitir que la información se comparta entre personas y/o máquinas. Una red de computadoras se puede definir como “dos o más computadoras conectadas de alguna manera por la cual son capaces de intercambiar información” (Donahue, Network Warrior, 2007).

A través del networking pueden comunicarse computadoras distintas; lo importante no es la marca, sino que todas hablen el mismo protocolo.

En una red de datos, la comunicación no es una conexión directa entre dos dispositivos: la información viaja saltando de nodo en nodo hasta el destino.

[PC A] → [Nodo 1] → [Nodo 2] → [Nodo 3] → [PC B]

3.2 Evolución cronológica de las redes

TDM, fibra óptica, ATM e IP son las cuatro etapas de una misma historia: cómo evolucionó el transporte de información a medida que crecía la demanda. Antes de TDM, cada comunicación requería su propio cable físico de punta a punta, lo que era insostenible a escala.

a) TDM — la primera idea: compartir el cable en el tiempo

Time Division Multiplexing resolvió el desperdicio físico: un solo cable, varias comunicaciones, cada una con su turno de microsegundos.

  • El canal se divide en ranuras de tiempo fijas (time slots).
  • Cada comunicación ocupa una ranura, cíclicamente.
  • Cada usuario tiene la ilusión de tener el canal entero.
Norma Canales Velocidad Uso
T1 (americana) 24 canales de voz de 64 kbps 1,544 Mbps EE.UU.
E1 (europea) 30 de datos + 2 de control 2,048 Mbps Argentina, Europa

Medio físico: cobre con PCM (Pulse Code Modulation).

Su limitación: la ranura queda reservada aunque no se use — en una llamada sin voz, ese tiempo se desperdicia. Y como las ranuras son fijas, la velocidad de cada usuario también lo es.

b) Fibra óptica y SDH — el salto físico

TDM seguía siendo válido, pero el cobre se quedó corto ante el crecimiento del tráfico. La fibra óptica no es un nuevo método de multiplexar — es un medio físico mejor: transmite luz en lugar de electricidad, lo que permite velocidades y distancias mucho mayores con menos pérdida.

Para organizar esa capacidad enorme se creó la jerarquía SDH (Synchronous Digital Hierarchy):

  • STM-1 (primer nivel) = 155 Mb/s
  • Los niveles superiores multiplican: STM-4, STM-16, STM-64…

💡 Punto clave: SDH sigue siendo TDM, solo que sobre fibra y a velocidades mucho mayores. La filosofía no cambió — sigue habiendo ranuras de tiempo reservadas.

c) ATM — atacar el desperdicio de TDM

Con la fibra había muchísimo ancho de banda, pero TDM seguía desperdiciándolo con sus ranuras fijas. Además, llegaron tráficos nuevos (datos, video) que no encajaban bien con la rigidez de la voz.

ATM (Asynchronous Transfer Mode) rompió con TDM:

TDM ATM
Ranuras de tiempo fijas Celdas de longitud fija y corta enviadas solo cuando hay datos
Canal reservado todo el tiempo No hay canal fijo: cada celda viaja independiente
Voz, datos, video → infraestructuras separadas Voz + datos + video sobre la misma red

Cada celda viaja por Virtual Paths (subdivididos en Virtual Channels) establecidos al inicio. Es decir: conmutación de paquetes (las celdas), pero con circuitos virtuales que recuerdan el modelo de circuitos. Corre nativamente sobre fibra.

d) IP — el ganador inesperado

ATM era técnicamente brillante pero caro y complejo. Mientras tanto, IP venía creciendo desde el mundo académico con una filosofía radicalmente más simple.

Característica Detalle
No orientado a conexión Cada paquete viaja independiente, puede tomar rutas distintas
Tamaño máximo de paquete 65 535 bytes teórico — en la práctica el MTU típico es ~1500 bytes (Ethernet); paquetes mayores se fragmentan
TTL (Time To Live) Contador que se decrementa en cada nodo; al llegar a 0 el paquete se descarta y el router envía un ICMP Time Exceeded (es lo que hace funcionar traceroute)
Direccionamiento IPv4 = 32 bits; IPv6 = 128 bits
Mejor esfuerzo (best effort) No garantiza entrega, orden ni tiempo. Si querés confiabilidad, va arriba (TCP)

IP ganó frente a ATM por simplicidad y escalabilidad, no por ser técnicamente superior en cada métrica. Hoy es la base de toda comunicación moderna.

Dos ejes para entender la evolución

Hay dos cosas distintas mezcladas en esta historia:

Eje Evolución
Medio físico Cobre PCM → Fibra óptica
Técnica de multiplexar TDM (ranuras fijas) → ATM (celdas) → IP (paquetes independientes)

Son ortogonales: hoy IP corre sobre fibra, pero también podría correr sobre cobre o sobre radio. TDM puede correr sobre cobre o sobre fibra (SDH).

🛡️ Implicancia histórica para ciberseguridad

Esta historia explica por qué IP no fue diseñado pensando en seguridad: nació en un entorno académico de confianza mutua. ATM, en cambio, tenía un modelo más cercano al telefónico clásico (con circuitos identificados). El triunfo de IP nos dejó una red global flexible pero sin autenticación ni cifrado nativo — eso vino después con capas añadidas (IPSec, TLS, DNSSEC).

3.3 ¿Qué es Internet?

Es una red de redes — una red conectada a otra de manera continua y simultánea.

Plataforma mundial de comunicaciones multimedia basada en: - Protocolo IP — direccionamiento numérico - DNS (Domain Name System) — direccionamiento por nombres humanos

Permite intercambio de información (voz, datos, video) en tiempo real o diferido, desde terminales fijas y móviles.

3.4 Organismos de estandarización

Para que dispositivos de fabricantes distintos (Windows, Linux, iOS, Android…) puedan comunicarse — compatibilidad e interoperabilidad —, los protocolos deben estar estandarizados.

Organismo Rol
ISO International Organization for Standardization. Publicó OSI.
IEEE Estándares 802.x (Ethernet, WiFi, Bluetooth…)
IETF Internet Engineering Task Force — publica las RFCs (Request for Comments). Define TCP/IP, HTTP, etc.
ICANN / IANA Coordinación global de DNS y asignación de IPs
LACNIC, ARIN, RIPE NCC, APNIC, AfriNIC Registros regionales de IPs
NIC Argentina Administración del .ar

3.5 🛡️ Implicancias de seguridad

  • Best-effort significa que IP no asume confianza ni garantía. Cualquier seguridad debe venir de arriba.
  • DNS se vuelve un blanco crítico: si te envenenan la resolución, podés terminar conectado al servidor del atacante creyendo que estás en el banco (cache poisoning, hijacking). DNSSEC busca mitigarlo, pero su despliegue es incompleto.
  • ICMP (TTL Exceeded, Echo Reply, etc.) es la base de herramientas legítimas (ping, traceroute) y también de reconocimiento ofensivo. Muchos firewalls lo restringen por eso.

TDM, fibra, ATM e IP no son tecnologías rivales sino respuestas sucesivas al mismo problema: cómo mover más información de forma más eficiente. La fibra cambió el medio físico; ATM e IP cambiaron la lógica de multiplexar. Que IP haya ganado define la red en la que vivís hoy: simple, escalable y diseñada para confianza mutua — por eso la seguridad se construye en capas superpuestas (TLS, IPSec, DNSSEC), no en la base.

Cliente-servidor
Modelo donde un cliente solicita y un servidor responde. Es la base de la web.
P2P (Peer to Peer)
Cada nodo es a la vez cliente y servidor. Ej: BitTorrent.
ARPANET
Red pionera (1969) financiada por el DoD de EE.UU. Origen de Internet.
TCP/IP
Suite de protocolos que reemplazó NCP en ARPANET y se volvió estándar global.
Cloud computing
Provisión de cómputo, almacenamiento y servicios a demanda por red.
E-commerce
Comercio electrónico: B2B, B2C, C2C. Requiere redes confiables y seguras.
