Direccionamiento IP

Guía de estudio — Universidad de Palermo · Ciberseguridad

🌐
¿Por qué existe IP?
Internet conecta dispositivos de distintos fabricantes, sobre cables, fibra, Wi-Fi o satélite. Para que todo esto funcione, se necesita un "idioma común": el Internet Protocol (IP). Su éxito se basa en cuatro pilares:
🔓
Estándares abiertos
Cualquier fabricante puede implementarlo. Los documentos son públicos: se llaman RFC (Request for Comments). También existen otros tipos de documentos: Military Standards (MIL STD) e Internet Engineering Notes (IEN).
🔌
Independencia física
IP funciona igual sobre Ethernet, Wi-Fi, fibra óptica o cualquier otro medio de transmisión. No le importa el "cable".
📍
Direccionamiento universal
Un esquema de direccionamiento amplio y común: cada dispositivo tiene una dirección única en toda la red, como una dirección postal global.
📚
Protocolos de alto nivel
Protocolos de alto nivel estandarizados: HTTP, FTP, DNS, SMTP… todos se construyen sobre IP. Es la "autopista" que todos usan.

Arquitectura en capas TCP/IP

No hay un acuerdo universal sobre cómo representar la jerarquía de los protocolos TCP/IP con un modelo de capas (se utilizan de tres a cinco capas según el autor). El modelo más común tiene 4 capas:
CapaRolEjemplos
AplicaciónAplicaciones y procesos que usan la redHTTP, FTP, DNS, SMTP
TransporteServicios de entrega de datos entre nodosTCP, UDP
InternetDefine el datagrama y maneja el enrutamiento → acá vive IPIP, ICMP, ARP
Acceso de redRutinas para acceder el medio físicoEthernet, Wi-Fi

Capa internet: el corazón de todo

La capa internet está ubicada sobre la capa de acceso de red. El protocolo IP (definido en RFC 791) es el corazón y protocolo más importante de esta capa. IP provee el servicio de entrega de paquetes sobre el cual están construidas las redes. Los protocolos sobre y debajo de la capa internet utilizan IP para entregar datos. Todos los datos fluyen a través de IP, entrando o saliendo, sin importar cuál sea su destino final.
⚙️
Funciones de IP
• Define el datagrama, que es la unidad básica de transmisión en internet.
• Define el esquema de direccionamiento de internet.
• Mueve datos entre la capa de acceso de red y la capa de transporte host-to-host.
⚡
Características de IP
• Es un protocolo connectionless: no intercambia información de control (handshake) para establecer una conexión nodo a nodo antes de transmitir.
• Es unreliable: no corrige ni detecta errores en la información. Otros protocolos (como TCP) hacen esas tareas.

Red de conmutación de paquetes

Internet es una red de conmutación de paquetes. Un paquete es un bloque de datos que lleva la información necesaria para ser entregado.

Funciona como una carta normal: lleva la dirección destino escrita en el "sobre" (el header). La información de la dirección es utilizada para "conmutar" los paquetes de una red a otra, hasta que llegue a su destino final.
Concepto clave: CADA PAQUETE VIAJA INDEPENDIENTE DE CUALQUIER OTRO PAQUETE. Pueden tomar rutas distintas y llegar en diferente orden.
📄
¿Qué es un datagrama?
El datagrama es el formato de paquete definido por el Protocolo Internet (IP). Es la unidad básica de transmisión. Tiene dos partes: el header (encabezado con información de control) y los datos.

Las primeras cinco o seis palabras de 32 bits del datagrama son información de control (el "header"). Se utiliza el IHL (Internet Header Length) para indicar la longitud del header. El header tiene la información necesaria para entregar el paquete (como el "sobre" de una carta).

Fragmentación

Distintas redes tienen un tamaño máximo de paquete llamado MTU (Maximum Transmission Unit). Hay fragmentación al pasar de un MTU mayor a uno menor. Los campos Identificación, Flags y Offset de fragmentación permiten rearmar los fragmentos en el destino.
Ejemplo: Ethernet tiene MTU de 1500 bytes. Si un paquete de 3000 bytes necesita pasar por esa red, IP lo divide en 2 fragmentos que se rearman en el destino.
🗺️
¿Qué es una dirección IP?
Las direcciones IP identifican unívocamente un punto de acceso (interfaz) a la red — no un dispositivo completo. Un router o un host multi-homed tienen varias direcciones IP (una por cada interfaz).

Tienen un significado global en la Internet. Son asignadas por una autoridad central: InterNIC (Internet Network Information Center).

Son números de 32 bits, expresados en notación decimal con puntos, byte a byte.

Para facilidad de los usuarios, se define un mapping estático de las direcciones IP con nombres más legibles mediante DNS (Domain Name Server). Ejemplo: google.com → su IP real.

Cada interfaz = una dirección

Cada interface de red (tarjeta de red) se le asigna una dirección lógica única de 32 bits. La dirección consta de una parte que identifica la red y otra que identifica el nodo (host):
R
Parte de RED — identifica la red física. La asigna InterNIC, tu ISP o tu administrador de red. Se usa para el ruteo (llevar el paquete a la red correcta).
H
Parte de HOST — identifica el dispositivo (interfaz) dentro de esa red. Se asigna localmente. Se usa para llegar al dispositivo exacto.

Esquema jerárquico

El esquema jerárquico consta de una parte que indica de qué red física se trata y otra que indica la interfaz o punto de conexión a la red (host).

En 1984 se agrega un tercer elemento en la jerarquía para lograr mayor flexibilidad: las subnets (subredes).

Los campos que componen la dirección eran originalmente de longitudes fijas predeterminadas; actualmente se elimina esta restricción con el classless addressing (direccionamiento sin clases).

El componente RED se utiliza para ubicar la red física de destino (ruteo) y el componente HOST se utiliza para identificar la interfaz dentro de esa red física.

Resolución de direcciones

Las direcciones IP son identificadores en una red virtual; en última instancia deben ser mapeadas a direcciones físicas de las distintas subredes (X.25, Ethernet, etc.). Este proceso se denomina resolución de direcciones.
Ejemplo: ARP (Address Resolution Protocol) convierte una IP a una dirección MAC de Ethernet.

Tres formas de escribir la misma dirección

Dirección especial: Loopback
La dirección 127.0.0.0 es la dirección de loopback:
• Se usa para comunicaciones de procesos en la misma máquina.
• Nunca es propagada a la red (no sale del dispositivo).

Notación CIDR (prefijo)

✂️
¿Qué significa la "/" en una IP?
La máscara de red define qué parte de la IP es RED y qué parte es HOST. La máscara también se puede especificar como la cantidad de bits a 1: 255.255.255.0 → tiene 24 bits a 1 → se escribe /24 128.223.254.10/24 → red: 128.223.254.0 | host: .10 Hoy día se utilizan indistintamente las dos notaciones (máscara completa o notación de prefijo con /).
Truco: /24 = las primeras 3 secciones son red. /16 = las primeras 2. /8 = solo la primera.

Direcciones privadas (no salen a internet)

Estos rangos están reservados para redes internas. Los routers no los propagan a internet público:
RangoEquivalenciaUso típico

Tu router de casa seguramente usa 192.168.x.x — es una IP privada. La IP que "ve" internet es otra distinta (la pública de tu ISP).
⚠️
Problemas del esquema de direccionamiento IP
El esquema original (clases A/B/C) no era muy flexible. Se perdían dos subredes en cada división. A medida que internet creció en los 90s, aparecieron varios problemas graves:
🗑️
Uso ineficiente del espacio
Los prefijos de longitud fija provocan un uso ineficiente en el espacio de direcciones. Una empresa que necesitaba 300 hosts debía tomar una Clase B (65.534 hosts) y desperdiciar ~65.000 direcciones.
📈
Agotamiento y escalabilidad
El crecimiento acelerado de internet evidenció la falta de escalabilidad: agotamiento de clases B e incremento del tamaño de tablas de ruteo al utilizar direcciones de clase C.
📱
Problema de movilidad
Codificar la red en la dirección IP implica que, si un host cambia de red, cambiará su dirección (problema conocido como IP Mobility). Esto rompe conexiones activas.
➖
Pérdida de subredes
Se perdían dos subredes en cada división: la dirección de red (.0) y la de broadcast (.255). En redes muy pequeñas esto es significativo.

En los 90's cambió el esquema (Classless)

¡Las viejas clases A, B, C no tienen significado ninguno en el internet de hoy!

Soluciones a corto plazo (IPv4)

🛣️
CIDR
Classless Interdomain Routing: los routers ya no consideran A, B, C como /8, /16, /24. Trabajan con prefijos de cualquier longitud (/20, /22, /25…). Permite asignar bloques exactos según necesidad.
📏
VLSM
Variable Length Subnet Masks: los routers no asumen que todas las subredes son del mismo tamaño. Distintas subredes dentro de la misma red pueden tener máscaras de diferente longitud.
Pregunta trampa de examen: ¿128.223.254.0/24 es una Clase C? Técnicamente el primer byte 128 cae en rango de Clase B, pero tiene máscara /24. Con CIDR la clase ya no importa — lo que importa es el prefijo.
✅
Solución definitiva
Estos problemas se solucionan a corto plazo en el contexto de IPv4 (con CIDR y VLSM). Pero son definitivamente solucionados en IPv6.
🚀
IPv6: la nueva generación
IP versión 6 (IPv6) es una nueva versión del IP diseñada como sucesora de la versión 4 de IP. IPv4 tiene 32 bits ≈ 4.300 millones de direcciones (ya agotadas). IPv6 usa 128 bits: permite más de 340 sextillones de direcciones.

Cambios y mejoras de IPv6

📖
Direccionamiento expandido
IPv6 incrementa el tamaño de las direcciones de 32 a 128 bits, para soportar más niveles de jerarquía de direccionamiento, un número mucho más grande de nodos direccionables y una autoconfiguración más simple.
📡
Multicast mejorado
La escalabilidad del enrutamiento multicast es mejorada al agregar un campo de ámbito ("scope") a las direcciones multicast.
🆕
Anycast
Se creó un nuevo tipo de dirección llamada "Anycast" utilizada para enviar un paquete a algún nodo que pertenece a un grupo de nodos (el más cercano).
⚡
Header simplificado
El formato de la cabecera es una simplificación del utilizado en IPv4, esto reduce el costo de procesamiento en nodos y routers.
🧩
Mejor soporte de opciones
Mejora el soporte de opciones y extensiones permitiendo un reenvío más eficiente, menos restricciones en la longitud de las opciones y mayor flexibilidad para introducir nuevas opciones en el futuro.
🏷️
Etiquetamiento de flujos
Incluye capacidad de etiquetamiento de flujos que permite marcar los paquetes para ser asociados a un "flujo" entre transmisor y receptor, pudiendo solicitar manejo especial (QoS).
🔒
Seguridad integrada
Tiene extensiones para autenticación y privacidad, integridad de datos, y confidencialidad de datos. En IPv4 esto era opcional (IPsec).
🚫
Sin broadcast
No hay direcciones broadcast en IPv6. Todo lo que antes era broadcast ahora se hace con multicast, que es más eficiente.

Tipos de direcciones en IPv6 (RFC 3513)

IPv6 provee un espacio de direcciones de 128 bits. Hay tres tipos de direcciones. Todas las direcciones IP se asignan a interfaces, no a nodos. Una dirección IPv6 unicast se refiere a una sola interface. Como cada interface pertenece a un solo nodo, cualquier dirección unicast de una interface puede ser utilizada para identificar el nodo.
TipoSignificadoEquivalente IPv4
UnicastUn paquete → una interfaz específicaDirección normal
AnycastUn paquete → el nodo más cercano del grupoNo existe en IPv4
MulticastUn paquete → múltiples interfaces suscritasClase D (224.x.x.x)

Formato: x:x:x:x:x:x:d.d.d.d, donde las 'x' son valores hexadecimales de seis campos más significativos (16 bits cada uno) y las 'd' son valores decimales de los cuatro campos menos significativos (8 bits cada uno, representación estándar IPv4).

Direcciones IPv6 con direcciones IPv4 embebidas

El mecanismo de transición IPv6 incluye una técnica para que los hosts y los routers de forma dinámica coloquen en un túnel paquetes IPv6 sobre una infraestructura de enrutamiento de IPv4. Existen dos tipos:
🔗
IPv4-compatible IPv6 address
Los nodos IPv6 que usan esta técnica tienen direcciones unicast IPv6 especiales con una dirección IPv4 global en los 32 bits menos significativos.

Formato: 80 bits de ceros + 16 bits de ceros + 32 bits de IPv4

::13.1.68.3 Nota: la dirección IPv4 utilizada debe ser una dirección unicast IPv4 globalmente única.
🗺️
IPv4-mapped IPv6 address
Se usa para representar las direcciones de los nodos IPv4 como direcciones IPv6.

Formato: 80 bits de ceros + 16 bits en FFFF + 32 bits de IPv4

::FFFF:129.144.52.38 La diferencia con el anterior: los 16 bits centrales son FFFF en vez de 0000.
