La capa de aplicación

Es la capa 7, la superior de OSI y TCP/IP. Proporciona la interfaz entre las aplicaciones que usamos y la red. En TCP/IP agrupa las tres capas superiores de OSI (aplicación, presentación, sesión). Distingue:

  • Aplicaciones reconocidas por la red: los programas que usa la gente (navegador, cliente de mail).
  • Servicios de la capa de aplicación: programas que preparan los datos para la red (transferencia de archivos, cola de impresión), transparentes para el usuario.
Aplicación, servicio y protocolo + Ampliado

Un mismo nombre puede referirse a las tres cosas: "Telnet" es la aplicación, el servicio y el protocolo. La aplicación crea el mensaje, el servicio da la interfaz con la red y el protocolo define las reglas y formatos.

DHCP — Dynamic Host Configuration Protocol

Servicio cliente/servidor (sobre UDP) que asigna automáticamente parámetros de configuración de red (IP, máscara, gateway, DNS). El servidor tiene una lista de IPs y las asigna conforme quedan libres, sabiendo quién tuvo cada IP, cuánto tiempo y a quién se la asignó después.

Método de asignaciónDescripción
AutomáticaIP permanente al cliente.
DinámicaIP por un tiempo limitado; el único que permite reutilizar direcciones liberadas.
ManualEl admin asigna la IP; DHCP solo la transmite.
El proceso DORA

El intercambio cliente-servidor: Discover → Offer → Request → Ack. (En las slides: DHCP Discover, Offer, Request, Ack/Nack, Inform).

DNS — Domain Name System

La "guía telefónica de Internet": traduce nombres de dominio (www.palermo.edu) a direcciones IP y viceversa, porque las personas usan nombres pero la red usa direcciones binarias. Usa una base de datos distribuida con estructura de árbol jerárquico.

Por qué DNS + Ampliado

Antes, ARPANET usaba un único archivo hosts.txt que cada host bajaba cada noche — no escalable. DNS lo reemplazó con administración distribuida y jerárquica. El nombre completo es el FQDN (Fully Qualified Domain Name), análogo a una ruta absoluta en un filesystem.

ConceptoDescripción
ZonaPorción del espacio de nombres administrada por un servidor.
Servidor primarioTiene los datos de la zona en archivos locales (modificación centralizada).
Servidor secundarioObtiene los datos del primario por transferencia de zona (redundancia).
Solo-cachéNo es autoritario; solo cachea consultas y respuestas.
ForwarderServidor autorizado a hacer consultas externas (Internet) por seguridad.

Tipos de consulta: recursiva (el servidor debe dar la respuesta final, típica cliente→servidor), iterativa (da la mejor respuesta que tiene, servidor→servidor) e inversa (IP→nombre, usa in-addr.arpa). TLDs: gTLD (.com, .net, .edu, .org, .gov, .mil) y ccTLD (códigos de país ISO-3166).

HTTP / HTTPS

HTTP (HyperText Transfer Protocol) transmite hipertexto (HTML y multimedia) en la web. Es orientado a transacciones con esquema petición-respuesta cliente-servidor, y sin estado (stateless). El recurso se identifica por su URL.

MétodoFunción
GETDevuelve el recurso de la URL.
HEADComo GET pero solo la cabecera (sin cuerpo).
POSTEnvía información del cliente (formularios).
PUTEnvía un recurso del cliente al servidor.
DELETEBorra el recurso.
OPTIONS / TRACE / CONNECTNegociación, depuración y túneles (proxy/SSL).
Cookies y estado + Ampliado

Como HTTP no maneja persistencia, usa cookies: fragmentos guardados en el navegador a pedido del servidor, recuperables en visitas posteriores (control de usuarios, preferencias, hábitos). En ciberseguridad, las cookies de sesión son un objetivo clásico de robo (XSS / session hijacking), y por eso importa HTTPS (HTTP sobre SSL/TLS, puerto 443).

Correo electrónico: SMTP, POP, IMAP

Esquema cliente-servidor con tres agentes: MUA (Mail User Agent, el cliente), MTA (Mail Transfer Agent, el servidor que transfiere) y MDA (Mail Delivery Agent, deja el correo en el buzón).

ProtocoloRolPuerto
SMTPEnvío / salida (MUA→MTA y MTA→MTA). Conexión TCP.25
POP3Recepción: descarga y suele borrar del servidor.110
IMAPRecepción: organiza en carpetas en el servidor, conserva estado.143
SMTP en detalle

Tres fases: handshaking (HELO), transferencia (MAIL FROM, RCPT TO, DATA — el mensaje termina con una línea con un solo ".") y cierre (QUIT). Mensajes en ASCII de 7 bits. Las respuestas llevan código: 4xx error temporal, 5xx error permanente. MIME permite adjuntos y ASCII extendido (codificación base64 / quoted-printable).

FTP — File Transfer Protocol

Transferencia de archivos entre hosts remotos (modelo cliente/servidor). Usa TCP con dos conexiones: puerto 21 de control (navegar directorios, comandos) y puerto 20 de datos (transferencia). Modos activo/pasivo, transferencia ASCII/binaria.

FTP vs. TFTP

FTP (RFC 959) sobre TCP: fiable, con carpetas. TFTP (RFC 1350) sobre UDP (puerto 69): muy simple, no fiable, sin carpetas ni encriptación, para archivos chicos. Cierra el círculo con la elección TCP/UDP de los Cap. 11 y 12.
