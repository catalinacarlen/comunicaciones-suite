Control de flujo

El control de flujo coordina el intercambio de datos para que el emisor no sature al receptor. Es una de las funciones más importantes de la capa de enlace. Dice al transmisor cuántos datos puede enviar antes de esperar un ACK (acuse de recibo). Como el receptor procesa más lento de lo que llega, usa un buffer; si se llena, debe avisar al emisor para que frene o pare — si no, descarta tramas aunque lleguen sin errores.

Dos tiempos clave

Tiempo de transmisión: lo que tarda el emisor en poner todos los bits de la trama en el medio (proporcional a la longitud de la trama). Tiempo de propagación: lo que tarda un bit en viajar de origen a destino (depende de la distancia).

Parada y espera (Stop & Wait)

El emisor envía una sola trama y espera el ACK antes de enviar la siguiente. Mantiene una copia hasta recibir el ACK e inicia un timeout: si no llega el ACK, reenvía. Las tramas y los ACK se numeran alternadamente 0 y 1 para identificarlas.

  participant A as Emisor
  participant B as Receptor
  A->>B: Trama 0
  B->>A: ACK 1 (listo para trama 1)
  A->>B: Trama 1
  B->>A: ACK 0 (listo para trama 0)
El ACK indica el número de la PRÓXIMA trama esperada
Desventaja

Solo hay una trama "en vuelo" a la vez → uso ineficiente del medio, sobre todo en redes rápidas o de larga distancia. El piggybacking (meter el ACK dentro de una trama de datos de vuelta) ahorra ancho de banda, pero no resuelve el problema de fondo.

Ventana deslizante (Sliding Window)

Permite enviar varias tramas a la vez antes de recibir un ACK. Requiere enlaces full-duplex y buffers ("ventanas") en ambos extremos. Las tramas se numeran en módulo 2k usando un campo de secuencia de k bits.

Fórmula clave

Con un campo de secuencia de k bits: la numeración es módulo n = 2k y el tamaño máximo de ventana = n − 1 = 2k − 1.
Ejemplo de cátedra: k=3 → módulo 8 → ventana = 2³−1 = 7.

  • La ventana de envío se mueve a la derecha al enviar una trama y al recibir un ACK.
  • El ACK (tipo RR = Receive Ready) incluye el número de la próxima trama esperada: "RR 3" = recibí todo hasta F2, mandame desde F3.
  • El receptor puede frenar con RNR (Receive Not Ready) y reanudar con un RR normal.

Detección y corrección de errores

El canal introduce errores (más en radio móvil). Hay dos grandes enfoques:

EnfoqueIdea
FEC (Forward Error Correction)El emisor agrega redundancia suficiente para que el receptor corrija el error sin retransmitir.
ARQ (Automatic Repeat Request)El receptor detecta el error y pide retransmisión.

Para detectar/corregir hay que agregar redundancia: cada bloque de k bits se codifica en una palabra de (k+r) bits llamada palabra código (codeword). La tasa del código es k/(k+r) y mide el ancho de banda extra.

Distancia de Hamming

La distancia de Hamming entre dos palabras es el número de bits en que difieren (se calcula con XOR y se cuentan los 1). Define cuántos errores se pueden detectar o corregir:

ObjetivoDistancia de Hamming mínima necesaria
Detectar d erroresd + 1
Corregir d errores2d + 1
Ejemplo de cátedra

Código con dmín = 5 → detecta d−1 = 4 errores y corrige (d−1)/2 = 2 errores.

Bit de paridad y CRC

Bit de paridad

Agrega un bit al final del bloque para que el total de unos sea par (paridad par) o impar (paridad impar). Es simple pero no detecta un número par de errores (se compensan).

CRC (Chequeo Cíclico Redundante)

Función que toma un flujo de datos de cualquier longitud y devuelve un valor fijo. El emisor genera una FCS (Frame Check Sequence) de r bits tal que la trama de k+r bits sea divisible exactamente por un divisor P. El receptor divide por P: si el resto es 0, no hay error.

Clave conceptual + Ampliado

El CRC sirve para integridad, no para confidencialidad: no es cifrado. Detecta errores de 1 bit, ráfagas menores que el FCS, número impar de errores (si P contiene el factor x+1) y la mayoría de las ráfagas largas. Por eso en ciberseguridad un CRC válido no garantiza que el mensaje no haya sido alterado intencionalmente — para eso se usan hashes criptográficos (MAC/HMAC).

ARQ — Automatic Repeat Request

Mecanismos de retransmisión ante errores. Tres variantes normalizadas:

VarianteCómo funciona
Parada y esperaUna trama por vez; numera ACK0/ACK1 para evitar duplicados.
Vuelta atrás N (Go-Back-N)Envía varias tramas; ante error envía REJ y retransmite la errónea y todas las posteriores.
Rechazo selectivo (Selective Reject)Envía SREJ y retransmite solo la trama errónea; conserva las demás. Más eficiente, más complejo.
Conexión + Ampliado

Estas técnicas son la base del comportamiento confiable de TCP (Cap. 11), que usa números de secuencia, ACK acumulativos y retransmisión — esencialmente una ventana deslizante con control de errores sobre IP.
