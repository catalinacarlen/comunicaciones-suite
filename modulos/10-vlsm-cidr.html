Conceptos básicos de ruteo

El ruteo es función del nivel IP. Para cada datagrama se decide, según su dirección de destino, hacia qué equipo enviarlo, usando tablas de ruteo (estáticas o dinámicas). Un equipo que solo es host no reenvía datagramas.

Campo de la tablaSignificado
Red de destinoRed a la que va el datagrama.
d/iSi se entrega directo al destino o indirecto a un router intermedio.
Dir. routerRouter por el cual se alcanza la red destino (próximo salto).
InterfaceSalida física por la que se envía (ej. eth0).
Envío directo vs indirecto

Directo: el destino está en la propia red física (mismo segmento). Indirecto: el destino está fuera → hace falta un router. El algoritmo busca: red conectada → ruta específica → ruta a la red → ruta por defecto → error.

Classful vs classless

ClassfulClassless

Los protocolos de ruteo no transmiten la máscara.Transmiten la máscara junto con cada dirección.

VLSM — Variable Length Subnet Masking

VLSM (1987) permite dividir un espacio de direcciones con máscaras de longitud variable, diseñando cada subred del tamaño justo para los usuarios que necesita. Extiende el prefijo hacia la derecha. Soporta subredes no contiguas.

Algoritmo VLSM (paso a paso)
  1. Ordená las necesidades de mayor a menor cantidad de hosts.
  2. Para el bloque más grande, calculá los bits de host: 2ʰ − 2 ≥ hosts requeridos.
  3. Asigná esa subred desde el inicio del espacio libre.
  4. Tomá el siguiente bloque libre y repetí con el próximo tamaño (tomando más bits).
  5. Seguí hasta cubrir todas las necesidades sin solaparte.
Ejemplo de cátedra (red 190.52.1.0)

Necesidades: 2 oficinas de 60 hosts + servidores/branches de 10. Solución: los de 60 hosts usan /26 (62 hosts) → .64/26 y .128/26; los de 10 hosts usan /28 (14 hosts) tomados de la subred .0/26 libre → .0/28, .16/28, .32/28, .48/28.

CIDR y sumarización (supernetting)

CIDR (Classless Inter-Domain Routing, RFC 1519) surgió por el agotamiento de las clases B y el crecimiento de las tablas de ruteo. Hace lo opuesto a VLSM: reduce el prefijo hacia la izquierda para resumir (agregar) varias redes en una sola entrada de la tabla de ruteo.

Beneficio de CIDR + Ampliado

Un router puede anunciar una sola ruta en vez de muchas: ej. 200.2.0.0/22 resume 200.2.0.0/24, 200.2.1.0/24, 200.2.2.0/24 y 200.2.3.0/24. Esto reduce el tamaño de las tablas y el tráfico de ruteo. Lo soportan BGP-4, OSPF, etc.

ARP — Address Resolution Protocol

ARP traduce una dirección IP a su dirección MAC (capa 3 → capa 2). Es imprescindible: para entregar un paquete dentro de una LAN se necesita la MAC del destino, no solo su IP.

Mecanismo
  1. A quiere enviar a B; busca la IP de B en su tabla ARP.
  2. Si no la tiene, hace un broadcast: "¿Quién tiene 192.168.0.1?" (destino MAC FF:FF:FF:FF:FF:FF).
  3. Todos reciben la trama, pero solo B responde con su MAC.
  4. B aprovecha y guarda la IP+MAC de A; A guarda la de B. Las entradas tienen tiempo de vida limitado.
Pregunta de cátedra (¡y de ciberseguridad!) + Ampliado

El paquete ARP viaja dentro de una trama Ethernet, no dentro de un paquete IP (ARP es un protocolo de capa de enlace/red auxiliar). En seguridad, este mecanismo de broadcast es el que habilita el ARP spoofing/poisoning: un atacante responde falsamente para hacerse pasar por otra IP (ataque Man-in-the-Middle).

ICMP — Internet Control Message Protocol

ICMP (RFC 792) está en la capa Internet y usa el datagrama IP (campo protocolo = 1) para enviar mensajes de control y error. Lo genera quien detecta el problema (host o router) e informa al origen.

Función de ICMPEjemplo
Control de flujo"Esperá un momento" (source quench).
Destinos inalcanzablesDestination Unreachable (tipo 3).
Redirección de rutasDentro de la misma red.
Chequeo de nodos remotosEl comando ping usa el mensaje echo.
Reportar timeoutsTTL expirado (lo usa traceroute).
Importante

ICMP informa errores pero no hace a IP confiable. No se generan ICMP sobre: errores producidos por ICMP, datagramas multicast/broadcast, ni fragmentos (solo el fragmento 0). El control de grupos multicast lo hace IGMP.
