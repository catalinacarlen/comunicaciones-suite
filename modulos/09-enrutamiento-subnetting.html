¿Qué es el subnetting?

Subnetting es dividir una red en dos o más redes más pequeñas. Se diseñó para resolver la escasez de direcciones IP y permite compartir una dirección de red entre varias redes físicas. Beneficios:

  • Uso eficiente de direcciones IP (no desperdiciar).
  • Reducir el tráfico y los dominios de broadcast (menos CPU, más velocidad).
  • Dividir según la estructura de la organización.
  • Agregar un nivel jerárquico invisible para las redes externas.
  • Más seguridad (filtros de paquetes entre subredes).

El campo SUBRED se le quita a HOST; significado local (RFC 950)

La máscara de subred

La máscara es un número de 32 bits que indica qué bits de la IP son red (bits en 1) y cuáles son host (bits en 0). Se puede escribir en decimal (255.255.255.0) o como prefijo CIDR (/24 = 24 bits en 1).

Direcciones que NO se pueden usar

No se pueden usar los valores todos 0 ni todos 1 en el campo host: todos 0 = la red, todos 1 = broadcast. Por eso se restan 2 al calcular hosts útiles.

El AND lógico

Para obtener la dirección de red/subred se hace un AND bit a bit entre la IP y la máscara:

IP 168.176.1.50 = 10101000.10110000.00000001.00110010
MÁSC 255.255.255.0 = 11111111.11111111.11111111.00000000
───────────────────────── AND ─────────────────────────
RED 168.176.1.0 = 10101000.10110000.00000001.00000000

Fórmulas clave

Memorizá esto para el parcial

Si tomás s bits para subred y quedan h bits para host:

Nº de subredes = 2s　·　Nº de hosts útiles = 2h − 2

Regla mental: cada bit más de máscara = el doble de subredes y la mitad de hosts (y viceversa). Truco del salto: 256 − (octeto de máscara) = tamaño de bloque de cada subred.

Subnetting paso a paso (ejemplo de cátedra)

Ejemplo 1: clase C con 3 bits de subred

Dada 204.15.5.0 /24, crear subredes usando 3 bits:

  1. 3 bits → 11100000 = 224 → máscara extendida 255.255.255.224 (/27).
  2. Nº de subredes = 2³ = 8.
  3. Quedan 5 bits de host → 2⁵ − 2 = 30 hosts por subred.
  4. Subredes: .0, .32, .64, .96, .128, .160, .192, .224 (saltan de a 32).

Primera subred 204.15.5.0/27 → hosts del .1 al .30, broadcast .31.

Comparación de máscaras (ejemplo 2)

/27 (255.255.255.224) → 8 subredes × 30 hosts. /28 (255.255.255.240) → 16 subredes × 14 hosts. Más bits de máscara = más subredes, menos hosts.

Conexión + Ampliado

Esto es solo "subnetting clásico" (todas las subredes iguales). Cuando cada subred necesita un tamaño distinto, se usa VLSM → Cap. 10. El enrutamiento que decide a dónde mandar cada datagrama se basa en las tablas de ruteo, que pueden ser estáticas o dinámicas.
