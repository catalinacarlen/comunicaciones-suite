La capa de transporte

Su tarea es entregar datos de la máquina origen a la destino de forma que se puedan rearmar correctamente (transmisión punto a punto). Responsabilidades: rastrear cada comunicación individual entre aplicaciones, dividir en segmentos y reunificarlos, e identificar la aplicación correspondiente. Los protocolos son TCP (confiable), UDP (liviano) y SCTP.

Puertos y sockets

Un puerto identifica la aplicación o proceso en el dispositivo. Rangos:

Socket

Un socket es el método de comunicación entre programas; cada extremo tiene uno.
Socket = Dirección IP + número de puerto. Tipos: Stream (TCP, fiable y ordenado), Datagram (UDP, sin conexión) y RAW (envío directo de paquetes IP).

TCP — Transmission Control Protocol

Definido en la RFC 793 (1981). Es orientado a la conexión, bidireccional, confiable (reliable) y de flujo de bytes (byte-stream). Garantiza que los datos lleguen exactos y en el orden correcto.

¿Por qué es confiable? PAR + Ampliado

TCP usa PAR (Positive Acknowledgment with Re-transmission): reenvía los datos hasta "escuchar" que el otro los recibió bien. Las 3 operaciones básicas: seguimiento de segmentos enviados, acuse de recibo (ACK) y retransmisión de lo no confirmado. Solo se reenvía la parte perdida, no todo el mensaje.

El costo de la confiabilidad

Toda esta confiabilidad genera sobrecarga: más datos de control (header de 20 bytes vs. los 8 de UDP) y posibles demoras. Hay un trade-off entre confiabilidad y carga sobre la red. Por eso TCP es un protocolo con estado (stateful): hace seguimiento del estado de la sesión.

Aplicaciones que usan TCP: navegadores web (HTTP), correo electrónico, transferencia de archivos (FTP), bases de datos — todo lo que necesita que todos los datos lleguen completos.

Establecimiento: el three-way handshake

Antes de transmitir datos, TCP negocia y establece una conexión intercambiando 3 segmentos (solo cabecera, sin datos):

sequenceDiagram
  participant C as Cliente
  participant S as Servidor
  C->>S: 1) SYN (seq = x)
  S->>C: 2) SYN + ACK (seq = y, ack = x+1)
  C->>S: 3) ACK (ack = y+1)
  Note over C,S: Conexión establecida → comienzan los datos
Three-way handshake: SYN → SYN/ACK → ACK
  1. SYN: el cliente pide conexión e informa su número de secuencia inicial.
  2. SYN + ACK: el servidor confirma y manda su propio número de secuencia.
  3. ACK: el cliente confirma → conexión establecida.
Conexión con ciberseguridad + Ampliado

Entender el handshake es clave en seguridad: el ataque SYN flood (DoS) abusa del paso 1 enviando muchos SYN sin completar el ACK, agotando los recursos del servidor. El escaneo de puertos con nmap también se basa en manipular estos flags (SYN scan).

Cierre de conexión

El cierre usa 4 segmentos (es full-duplex, se cierra cada sentido por separado): FIN → ACK de un lado, y FIN → ACK del otro. Quien envía el último ACK espera un tiempo (TIME-WAIT) por si se pierde y hay que reenviarlo.

El segmento TCP

El header TCP tiene una parte fija de 20 bytes y una opcional de hasta 40. Campos clave: puerto origen/destino, número de secuencia, número de ACK, flags (SYN, ACK, FIN…), tamaño de ventana (16 bits) y checksum.

Número de secuencia inicial (ISN)

Para no confundir segmentos de conexiones viejas ("reencarnaciones"), se usa un ISN de 32 bits generado por un reloj cuyo bit menos significativo se incrementa cada ~4 µs. El espacio de secuencia va de 0 a 2³²−1.

Control de flujo y entrega en orden

TCP numera y secuencia los segmentos para rearmarlos en orden aunque lleguen por rutas distintas. Usa una variante de ventana deslizante (ver Cap. 5) pero contando bytes, no tramas. El ACK es acumulativo: un ACK de X significa "recibí todo hasta X−1".

Tamaño de ventana (window size)

Campo de 16 bits que indica cuántos bytes puede aceptar el receptor. Se acuerda en el handshake. Si el receptor se satura o la red se congestiona, achica la ventana → baja la tasa de transmisión, evitando pérdidas y retransmisiones. Así TCP equilibra velocidad y confiabilidad.

Comparación adelantada

Todo lo contrario de TCP es UDP (Cap. 12): sin conexión, sin estado, sin control de flujo, header de solo 8 bytes — rápido pero sin garantías.
